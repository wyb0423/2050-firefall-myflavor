# Paradox Script 实现要点

## 从上下文验证语法

同一 trigger 或 effect 在 country、state、building、character、market、strategic region 等作用域下可用性不同。写代码前，在原版或已成功运行的 Mod 中寻找：

- 相同命令；
- 相同进入作用域；
- 相同参数形态；
- 相同文件类型。

沿调用链记录每一步作用域变化。IDE 语法提示不理解全部游戏版本和 Mod 扩展，因此只能辅助，不能替代启动解析与运行验证。

## 分清脚本类别

- trigger 判断状态，不应产生副作用；
- effect 改变状态；
- script value 计算数值；
- modifier 定义可叠加的修正；
- on_action 提供调度入口；
- event、journal、decision 和 scripted button 提供不同的状态机或 UI 入口。

不要把某一类别中的合法结构直接复制到另一类别。使用 `has_*`、`add_*`、`remove_*` 一类命令时，分别核实它是 trigger 还是 effect，以及合法 scope。

## 布尔条件

- 同一条件块中的并列项通常是 AND；
- `OR = { ... }` 中任一项成立即可；
- `NOT = { ... }` 的作用范围由括号决定；
- `if`、`else_if`、`trigger_if` 和 `trigger_else` 的可用位置不同。

把复杂条件还原成简短布尔表达式并核对。例如 `A AND (B OR C)` 与 `(A AND B) OR C` 的触发范围差异很大。日志最好记录决定分支的原因，而不仅是“条件成立”。

## 初始化、周期逻辑和幂等性

- 新游戏初始化、旧存档补发和周期刷新是三个不同问题。
- ensure effect 应可重复执行，不重复添加对象，也不无意重置有限期限。
- 选择最低必要频率。全世界遍历或建筑遍历不应无理由挂在高频 pulse 上。
- 当数值来源会动态变化时，周期刷新应先移除自身贡献，避免递归累加。
- 对一次性迁移设置版本变量，使旧迁移不会永久占用周期路径。

## 本地化与编码

- 新增任何玩家可见对象时，同步添加所需语言的本地化键。
- 保持文件头、编码、BOM、缩进和命名风格与当前项目一致。
- 技术 ID 用于脚本和诊断；显示名与说明使用本地化键。
- 修改脚本文件时不要顺带格式化或重编码无关文件。

## 自制解析器

批量分析或生成脚本时：

- 标识符允许字母、数字、下划线和连字符；
- 用括号深度提取嵌套块，不依赖单个跨层正则；
- 正确处理注释、字符串和操作前缀；
- 保留列表顺序与重复语义；
- 数值解析支持正负号、小数和脚本化表达式；
- 无法可靠解析时停止并报告，而不是静默使用空集合。
