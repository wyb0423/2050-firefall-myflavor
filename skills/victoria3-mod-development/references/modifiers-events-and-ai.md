# Modifier、事件与 AI

## Modifier 数值语义

先在当前版本中找到同名 modifier 的原版先例，确认：

- `add` 是固定增量还是按其他层级缩放；
- `mult` 表示相对增量还是最终倍率；
- modifier 作用域和聚合位置；
- 动态 `multiplier` 是否缩放整个 modifier；
- 多来源之间是相加、相乘还是有上限。

用户要求“严格等于原值的某个倍率”时，应先写出完整公式，再决定 modifier。若目标只有 additive 接口，可能需要镜像完整未修改值；若读取的 accessor 包含当前 Mod 自身贡献，刷新前必须扣除或隔离自身贡献，防止每次周期累加。

## 有限期限和动态刷新

- 有限期限 modifier 应只在需要时添加；周期 ensure 不应无意续期。
- 永久 modifier 仍需考虑旧存档是否已有错误版本。
- 移除 modifier 可能立即改变后续 accessor 的计算图；需要旧值时先捕获。
- 把需要动态倍率的 modifier 与普通百分比 modifier 分开，避免动态 multiplier 同时放大无关字段。

## 事件和 Journal 状态机

复杂功能先定义状态与转移，再写脚本：

```text
未初始化 -> 可用 -> 运行中 -> 成功 / 失败 / 取消
```

为每个入口规定前置条件、一次性效果、持久状态和清理路径。所有取消、失败和外部变化路径都应清理临时变量和 event target。Journal、decision 或 button 只是入口和可视化，不应让同一状态同时由多个不协调的调度器维护。

## AI 权重

将 AI 行为拆成不同层级：

1. 是否考虑某类行动；
2. 对候选区域或目标的评分；
3. 在目标内部选择具体对象；
4. 同时行动数量和冷却。

优先修改与问题直接对应的层。改善区域选择不应顺带改变并发上限；改善局部形状不应无意禁止所有远距离目标。

使用乘数或加权条件时，避免把偏好写成绝对禁令，除非用户明确要求。无法直接取得距离等量时，可以使用同战略区域、邻接、已有存在、市场连接或跨海状态等可解释代理，但要说明近似及边界。

## 性能

- 评分 trigger 可能被 AI 高频调用，应保持轻量。
- 把不变条件提前，避免在深层循环重复计算。
- 优先使用原生较低频 pulse，而不是高频 pulse 加日期判断。
- 对全局 `every_*`、嵌套 `ordered_*` 和市场/建筑遍历估算调用规模。
- 调试日志在验证后应可关闭或控制频率，避免日志轮转掩盖问题。
