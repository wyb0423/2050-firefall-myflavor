# FFPA 第二轮全仓语言审校设计

日期：2026-09-02
状态：静态实施完成，待游戏内目测

## 1. 背景

第一轮已经完成 GRE → BYZ 成立链、TUR/BYZ 复归成功事件、四项常驻治理日志、十五项地区建设、TUR 三场地区治理会议、国家与政府称谓以及 README 的重点改写。同时，运行时已经加入复归目标州直接前所有者的动态追踪，并完成 TUR/GRE/BYZ 玩家可见入口的严格身份门控。

第二轮不再围绕单个明显问题补丁式修改，而是通读本项目全部玩家可见文本，检查第一轮改写前后的接缝、尚未触及的短文本、机械说明与叙事正文之间的一致性，以及英文和简中的语气差异。目标仍是增强“历史风味 + 2050 核战后再拓殖”背景，不扩展玩法系统。

本轮以当前 `main` 为基线，保留 `260527d` 的 JE/变量提示修正与 `4d7d7cf` 的进度条显示改进。

## 2. 目标

1. 让全部玩家文本处于同一世界观时间轴：大火后的即时重建、国家重新形成后的整合、以及数十年后的常态治理应使用不同语言。
2. 让复归战争、地区建设和治理会议准确区分前所有者、战争对象、当地社会与本国国家机关，不把开局实体固定成几十年后的叙事对象。
3. 将古典、拜占庭、奥斯曼和十九世纪民族主义材料写成被当代国家重新发现、选择和利用的档案、制度记忆、政治修辞与法统资源，而不是未经解释的连续现实。
4. 减少模板句、翻译腔、重复身份提示和空泛的“现代化／永久强化”，使每条内容有明确的地点、制度矛盾和政治主体。
5. 保持事件正文、JE reason、按钮、进度条、modifier 与实际脚本效果一致。
6. 保持英文与简中键集合一致；两种语言分别自然，不以逐词互译代替语义一致。

## 3. 非目标

- 不修改玩法、数值、触发条件、效果、AI、调度频率或状态机。
- 不重命名技术 ID、持久变量、事件 ID、JE、modifier 或进度条对象。
- 不改变复归前所有者追踪的语义、延迟或清理路径。
- 不重新设计 TUR 三条建国路线、BYZ 复归分区、共同体三轴或四项常驻治理日志。
- 不修改 metadata 版本、依赖、显示名称或发布标签。
- 不把外部 Core Balance、Building Pruning 或 Auto PM Adapter 的文本复制回本仓库。
- 不为了“历史感”新增无法由可靠资料支持的精确日期、人物、制度沿革或连续性断言。

## 4. 审校范围

### 4.1 直接修改范围

- `localization/english/ffpa_l_english.yml`
- `localization/simp_chinese/ffpa_l_simp_chinese.yml`
- `localization/english/ffpa_turkish_flavor_l_english.yml`
- `localization/simp_chinese/ffpa_turkish_flavor_l_simp_chinese.yml`
- `localization/english/ffpa_permanent_governance_l_english.yml`
- `localization/simp_chinese/ffpa_permanent_governance_l_simp_chinese.yml`
- `localization/replace/english/zzzz_ffpa_country_variable_tooltip_l_english.yml`
- `localization/replace/simp_chinese/zzzz_ffpa_country_variable_tooltip_l_simp_chinese.yml`

`README.md` 只在游戏内最终术语变化导致说明失真时同步窄改；不会再次整体重写。

### 4.2 只读核对范围

全部 `common/` 与 `events/` 文件用于核对：

- 文本对应的真实 trigger、effect、modifier、持续时间和清理路径；
- 动态国家、州、文化、政府、利益集团和前所有者作用域；
- 新游戏、旧存档、失败、撤回和标签变化路径；
- 玩家实际能看到某段文本的国家身份与内容阶段。

原版、Firefall 与 Tech & Res 的同名本地化和被覆盖对象只用于建立最终加载结果，不在上游目录写入修改。

## 5. 方案比较与选择

### 5.1 采用：按内容链逐模块审校

按共享身份 → GRE/BYZ → TUR → 常驻治理 → 地区建设与西方整合的顺序处理。每个模块同时核对英文、简中和脚本语义，再进入下一模块。最后追加全仓术语横扫。

优点是同一事件链的叙事声音、时间位置和因果关系能够一起判断，也能保护最新的机制修正。缺点是需要在末尾额外检查跨模块重复词和译名；本设计通过独立的全局横扫解决。

### 5.2 未采用：按问题类型横扫

先改全部时代错置，再改全部对象误认、模板化和翻译腔。检索效率高，但容易在不知道完整事件链的情况下修改单句，使前后语气割裂。

### 5.3 未采用：中文重写后反推英文

中文表达可以更快形成风格，但英文容易退化为中文句法的直译，且两轮分离审校增加机制语义漂移风险。

## 6. 统一审校准则

### 6.1 时间层次

- 大火初期：强调断裂、人口流散、资料丢失、基础设施停摆和紧急恢复。
- 国家重新形成期：强调继承政权之间的战争、妥协、登记、统一标准和国家机器扩张。
- 领土取得后的建设期：强调已经处于本国主权下的行政、交通、市场、电网、港务、地籍和产业整合。
- 常态治理期：强调此前重建方案产生的制度遗产、利益集团、财政承诺、地方中介和结构性压力，而不是继续把全国写成刚被炸毁的废墟。

每个文本按实际解锁阶段选用其中一种，不用“大火之后”作为所有段落的通用开头。

### 6.2 历史材料的叙事位置

- 查士丁尼、罗马、拜占庭、奥斯曼、高门、军役授田和伟大理想等材料可以保留。
- 当代角色接触这些材料的媒介应当可理解：幸存档案、复制件、教会与学校记忆、法典片段、地名、礼仪、政治宣传或制度复刻。
- 使用历史名称不自动意味着制度、人口或国家拥有连续不断的生存史。
- 国家可以主动制造传统、争夺解释权或利用古旧名号解决现代问题；文本应体现这种当代能动性。

### 6.3 叙事对象

- TUR/BYZ 复归成功事件只在动态对象可靠时点名最后一个关键州的直接前所有者；否则使用中性 fallback。
- 不把直接前所有者写成全部目标领土的唯一敌国，也不把所有权变化必然写成战争征服。
- 地区建设和治理会议发生在领土已经纳入国家机器之后，不再把当地写成仍独立的港邦、部落议会或松散政权。
- 可以描述当地既有行政、企业、交通网络、宗教社群、地主、城市机构和战后形成的国家遗产，但不能凭空给出未由脚本或世界设定支持的政治实体。

### 6.4 模块声音

- 共享身份与成立链：档案重见天日、国家重新拼合、旧名号被当代政治重新解释。
- GRE：海岛与本土继承政权重新汇合后的争论，既有民族认同，也有对过度扩张的恐惧。
- BYZ：使用公共体、帝国机关、罗马名号和新罗马等词，但重点是现代复兴国家如何制造并维持这些制度。
- TUR 高门路线：宪章、行省中介、宫署和共同体妥协。
- TUR 共和国路线：议会授权、文武关系、公民国家和对旧帝国结构的选择性继承。
- TUR 重建总署路线：地籍、工程、开发机构、技术官僚和国家能力。
- 常驻治理：语言更克制、更制度化，表现长期成本和结构性矛盾。
- 地区建设：突出具体区域的交通、港务、能源、产业与行政遗产，避免十五条日志使用同一模板。

### 6.5 机械文本

- 标题和短说明优先简洁；JE reason 可以同时承担世界观与完整规则说明。
- tooltip 不隐瞒真实门槛，也不承诺脚本没有实现的结果。
- 明确区分一次性、限时、衰减和永久效果。
- 保留最新共同体进度条的数值显示、hover 条件统计和 `country_var_equal` 通用提示修正；只有发现真实语义或语言错误时才窄改。

### 6.6 双语标准

- 英文和简中表达同一事实、因果与态度，但允许不同句式。
- 英文避免过密的抽象名词串联和中文式并列；简中避免逐词翻译、过长定语和不自然的被动句。
- 专名在模块内稳定，重点包括 `Public Authority／公共权威`、`Public Polity／公共体`、`Military Households／军役户`、`Dynatoi／权门` 及已经确认的地区名称。
- 动态本地化、颜色标记、换行、变量和作用域表达式原样保留，除非它本身就是已确认的问题。

## 7. 实施顺序

### 7.1 建立逐键清单

提取八份文件的键集合，按以下类别标记：名称、短描述、JE reason、事件正文、flavor、选项、tooltip、modifier、进度条和覆盖键。对每个候选问题记录：

- 所属模块与事件链位置；
- 对应脚本对象；
- 问题类型；
- 英文与简中是否同时存在；
- 是否属于有意覆盖上游的键；
- 建议保留、窄改或重写。

### 7.2 模块化改写

依次处理：

1. 国家、文化、政府、党名、利益集团、意识形态、国家集团名称和通用 UI；
2. GRE 民族主义与 GRE → BYZ 成立链；
3. BYZ 共同体、首都、复归战争与西方整合；
4. TUR 三条建国路线、安纳托利亚工程、海峡与边疆前线；
5. TUR/BYZ 四项常驻治理日志；
6. 十五项地区建设与 TUR 三场地区治理会议；
7. 通用 fallback、短 tooltip 和 modifier 描述。

每一组先核对脚本，再成对修改英文与简中，不在全仓执行无上下文的机械替换。

### 7.3 全局横扫

模块改写完成后，统一搜索：

- `restore`、`rebuild`、`modernize`、`permanently`、`ruins` 及中文对应词的重复和阶段错置；
- “作为拜占庭／土耳其”等由可见条件已经表达的身份赘语；
- 港邦、部落、松散政权、幸存者政权等可能错误固定开局对象的词；
- 前所有者、战争对象、地方精英、国家机关和居民之间的主语混淆；
- `Law／法统` 与 `Public Authority／公共权威` 等已统一术语的回退；
- 英文国家形容词、动态国家名和单复数语法；
- 同一效果在正文、选项与 tooltip 中的说法不一致。

## 8. 历史调研规则

本地游戏与依赖文件决定技术对象和 2050 世界的既成事实。需要新增具体历史称谓、制度关系或地理名称时，再查询可靠的一手或学术来源；无法可靠确认的细节使用更一般的制度语言，不以记忆补写。

历史调研只服务于措辞，不借机扩展宣称、领土、文化、宗教、政府或 modifier。

## 9. 验证

### 9.1 静态验证

- 八份本地化文件保持正确语言头和 UTF-8 BOM；
- 三组主英文／简中本地化分别保持完全相同的键集合；
- 覆盖目录的英文／简中键集合一致；
- 修改行的引号、转义、颜色标记、变量和动态表达式完整；
- 同一文件无意外重复键；有意覆盖只存在于登记的 replace 或主加载接缝；
- 所有本地化键能找到自有或上游调用方，新增引用能在最终加载栈解析；
- `.metadata/metadata.json` 仍可解析且内容不变；
- `git diff --check` 无新增空白错误；
- 不把最新进度条和变量提示修正回退。

### 9.2 语义验证

- 逐项对照事件选项、JE 完成/失败路径、modifier 与实际效果；
- 动态前所有者 named/fallback 文本不改变已登记语义；
- 地区建设不承诺宣称、首次主权或未实现的国家级奖励；
- 常驻治理说明准确反映计时、警告、破裂、修复、衰减和永久结果；
- 新游戏、旧档补发和周期刷新文本不互相矛盾。

### 9.3 游戏内目测

静态实施后仍需在游戏内检查：

- 长 JE reason、事件正文和 tooltip 是否截断；
- `\n\n`、颜色标记和动态值是否按预期显示；
- 动态国家名、前所有者名、政府称谓、党名和国家集团候选名称的最终语法；
- 共同体进度条 hover 与最新机制是否一致；
- 中英文在实际 UI 宽度下是否需要进一步压缩。

无法启动游戏时，不把静态文本存在描述为运行时已验证。

## 10. 交付与 Git 边界

实施交付分别报告：

- 修改了哪些本地化模块和代表性问题；
- 是否触及上游覆盖键、README、存档 API 或跨模块接口；
- 双语、格式、引用与最终加载栈验证结果；
- 仍需游戏内目测的文本；
- 当前分支、工作树及用户既有提交状态。

本轮设计本身不授权 Git 提交或推送；只有用户明确要求时才执行。

## 11. 成功标准

完成后，玩家从国家成立、复归战争、建设计划到常驻治理读到的是同一个 2050 大火后世界，但不同阶段不会使用同一种“废墟重建”声音。历史名称提供制度资源与政治张力，而不是把古代或十九世纪直接搬到未来。战争和领土文本能够准确指向动态前所有者或自然降级，已收复地区被视为国家统治下需要整合的成熟社会。英文与简中分别自然，所有规则说明与现有脚本一致，并且不改变任何玩法和存档接口。
