# FFPA 国家风味设计工具箱

日期：2026-09-04

状态：持续维护的创作参考；不是强制清单或验收门槛

## 1. 文档定位

本工具箱总结 FFPA 既有国家风味开发中已经证明有效的设计逻辑，供以后开发其他国家或地区时选用。它回答“希望玩家经历什么、为什么这些内容属于这个国家”，不替代 `AGENTS.md` 对最终数据库、模块边界、本地化、存档兼容和验证的硬性要求。

这里的组件全部可选：新国家不必达到既有东地中海内容的规模，也不必覆盖身份、事件、日志、利益集团、领土与长期治理的全部层级。只要一个较小的内容组合已经完整兑现核心体验，就应停在那里。没有选择的组件不构成缺项。

本工具箱也不是封闭分类。以后实际模块产生新的、可复用的风味设计要素时，可以继续补充；不要求旧模块反向补齐新要素。

## 2. 核心设计哲学

### 2.1 历史是材料，不是剧本

历史名称、制度、版图、人物记忆和政治语言应当成为灾后国家主动解释和利用的资源，而不是跨越大火后仍原样运转的连续现实。

历史沉浸感主要来自可信的制度因果：幸存档案如何被发现，旧名号为何重新有用，哪些群体从某种解释中获益，国家又为恢复这种传统付出什么代价。单纯堆砌古称、引文和象征物不能替代这条因果链。

### 2.2 国家身份是一项政治工程

成立 tag、恢复国号或更换政府名称只是身份工程的开端。成熟的国家风味应让玩家看到：谁提出这种身份、谁执行它、谁抵制它，以及它最终改变了哪些制度、政治联盟和国家能力。

路线一旦经过明确结算，就应成为这局游戏的历史事实。后续短期法律或政体变化可以产生新的摩擦，但不应静默改写玩家已经作出的建国选择。

### 2.3 用独有矛盾驱动玩法

每个国家优先寻找一个无法靠单向堆数值解决的核心矛盾，例如中央能力与地方执行、共同身份与地区差异、军事动员与社会基础、技术治理与政治授权。这个矛盾决定最值得采用的玩法组件。

国家之间的差异应体现为不同的决策结构，而不只是不同文本包裹下的同一种进度条。若现有循环已经能表达新国家的问题，应复用原生机制；若不能，再设计最小的新循环。

### 2.4 文本、政治身份与玩法后果互相证明

一个主题最好至少落到以下三个层面的两个层面：

- 文本如何解释它；
- 国家、政府、利益集团或地区如何显示它；
- 玩家通过什么选择、成本和后果实际体验它。

只有名称而没有行为，容易沦为装饰；只有 modifier 而没有政治含义，容易沦为数值包。三层不必全部出现，但出现的层面必须指向同一个国家命题。

### 2.5 奖励行动，不奖励标签本身

强力或永久收益应当来自玩家完成的建设、改革、妥协或长期维持，而不是因为国家使用了某个 tag 就自动获得。地区成果优先落在真正参与工程或制度整合的州；全国效果应说明它代表的国家机关或政治安排。

领土、后续内容的开放、完成状态和新的治理能力本身都可以是奖励，不必在每个节点额外叠加全国增益。

### 2.6 成功不是内容终点

成立国家、取得疆域或完成重建解决的是“国家能否出现”，长期风味还可以追问“它能否持续治理”。后期内容宜表现早期选择留下的制度余震、财政承诺、政治联盟和结构性压力，而不是让国家永久停留在灾后废墟阶段。

并非每个国家都需要常驻系统。只有当成功之后仍存在一个具有独特决策价值的问题时，才值得增加长期治理内容。

### 2.7 尊重沙盒世界的真实状态

Firefall 开局实体、几十年后的领土所有者、政体、法律和利益集团力量都可能变化。文本只能陈述脚本能够证明的事实：能可靠识别对象时使用动态叙事，不能识别时自然降级；不要把宣称写成主权，把所有权转移写成战争胜利，或把某种法律写成无条件存在。

### 2.8 不追求国家之间的内容对称

不同国家可以只有一次成立抉择，也可以拥有贯穿数十年的制度循环。内容规模、组件数量和奖励种类不需要相等。应追求的是体验完整、主题清楚和内部因果一致，而不是栏目齐全。

## 3. Firefall 叙事时间层次

同一个国家可以经历多个时间层，但不要求每层都有专属内容：

| 时间层 | 主要问题 | 适合的叙事语言 |
|---|---|---|
| 灾变余波 | 人口、资料与基础设施如何幸存 | 断裂、失散、打捞、应急恢复 |
| 国家重新形成 | 分裂继承者如何建立共同权威 | 妥协、登记、统一标准、确认法统 |
| 制度定型 | 新国家选择成为哪一种政治工程 | 授权、宪章、代表、规划、组织 |
| 领土纳入 | 已取得地区如何进入国家网络 | 接入、对勘、扩容、协调、统一制度 |
| 常态治理 | 重建方案留下了什么长期矛盾 | 维护、平衡、承诺、压力、修复 |

静态文本无法知道准确年份，因此应按内容的实际解锁阶段选择语言。不要让所有事件都以“大火之后”开头，也不要把晚期成熟社会继续写成刚从废墟中醒来。

## 4. 可选设计工具箱

| 组件 | 它解决的问题 | 可形成的玩家体验 |
|---|---|---|
| 身份外壳 | 国家在地图、政治与外交界面中如何被辨认 | 动态国名、政府称谓、旗帜、党名、集团名称等形成一致声音 |
| 建国或再解释链 | 旧国家名称为何在灾后重新成立 | 玩家参与法统与国家目标的选择，而不是无条件复刻历史国家 |
| 路线身份 | 同一国家可以成为哪些不同的政治工程 | 互斥路线留下持久历史，并改变后续内容的语言和边界 |
| 利益集团塑形 | 谁支持、阻挠或执行国家工程 | 名称、Trait、意识形态和政治反应把制度冲突放进原生政治系统 |
| 阶段性事件 | 抽象制度变化由谁推动、在哪里转折 | 用人物、机构和场景解释关键节点，而不是以事件数量制造丰富度 |
| 有限目标日志 | 一项重建、整合或改革如何形成中期方向 | 条件可读、进退有因果、失败可恢复，奖励与实际行动相称 |
| 领土议程 | 国家为何以及能够向哪里扩张 | 路线、次序、期限和外交成本约束历史诉求，同时保留沙盒征服自由 |
| 地区建设 | 已取得领土如何真正进入国家网络 | 交通、行政、市场、能源和产业整合在实际建设州留下遗产 |
| 制度结算 | 一段建设最终留下什么国家结构 | 独立的永久选择产生机会成本，不设置隐藏的唯一正确组合 |
| 常驻治理 | 成功后的国家仍需长期管理什么 | 用平衡、储备、支柱、结构压力或未来的新循环表达持续治理 |
| 动态叙事 | 文本如何响应变化中的世界 | 可靠时具体，证据不足时克制，避免伪造战争、主权与政治事实 |
| 迁移与兼容 | 内容如何跨越新旧存档和上游变化 | 幂等补发、显式状态、最小覆盖和可恢复的清理路径 |

以后出现新的有效组件时，可直接加入本表。新增组件应描述它解决的设计问题，而不是绑定某一国家的专名、事件或技术 ID。

## 5. 组合方法

以下是建议的思考顺序，不是必须遵循的开发流程。

### 5.1 先写一句玩家幻想

用一句话说明玩家为什么要游玩这个国家，且这句话应描述一种行动或困境，而不只是历史标签。例如，“把分裂的继承者塑造成能够维持多地区统治的国家”比“恢复一个古老帝国”更能指导玩法。

### 5.2 找到核心矛盾

把幻想改写成两个都具有合理性的方向。好的矛盾不要求一方永远正确，也不能仅靠更高 GDP 自动消失。它应能持续产生选择、联盟、成本或风险。

### 5.3 选择一个锚点循环

优先选择一个最能表达核心矛盾的组件作为锚点，例如路线结算、有限日志、领土议程或长期治理。其他组件只用于解释、反馈或延伸这个循环。

不要因为既有国家拥有某种系统，就默认新国家也需要同类系统。两个国家若面对不同问题，应允许其玩法结构明显不对称。

### 5.4 增加最少的身份反馈

选择能让玩家看见结果的最小反馈组合。一次路线选择可能只需要政府称谓和两个利益集团变化；一项地区工程可能只需要州 modifier 与后续事件。无需为了“完整套装”填满所有身份数据库。

### 5.5 用事件连接，而不是填充

事件适合承担提案、危机、结算和后果解释。没有新的选择、信息或状态变化时，不必增加事件。重复弹窗不是叙事节奏。

### 5.6 到兑现玩家承诺时停止

如果移除某项内容不会削弱核心幻想、独特决策或阶段因果，就不应仅为增加体量而保留。以后出现真实缺口时再扩展，比预先搭建通用框架更安全。

## 6. 常用设计模式

这些模式可单独使用，也可以重组或替换。

### 6.1 身份由多种弱信号共同建立

国家名、政府名、党名、利益集团和集团候选名称不必全部独特制，但被选择的部分应共享同一制度语言。身份效果优先使用原生 UI 与既有槽位，避免为少量展示另造界面或周期系统。

### 6.2 路线选择形成路径依赖

互斥路线应改变后续可见内容、政治角色或目标边界，而不只是发放三个不同 modifier。路线定型后不因普通政体切换自动改变；真正需要改写路线时，应由新的显式政治结算完成。

### 6.3 利益集团既提供能力，也制造约束

独特 Trait 不应只有忠诚奖励。被塑造成国家支柱的集团也可以在不满时暴露该制度的弱点。优先替换少量最能表达身份的原生槽位，保留其他原版行为与兼容空间。

### 6.4 进度反映状态，而不是只计算等待时间

日志进展应来自玩家能够影响的国家状况。条件恶化时可以停滞或倒退，但通常不应无解释地全部清零。UI 应让玩家知道当前变化来自什么、何时会失败以及如何恢复。

### 6.5 扩张是受约束的国家议程

历史诉求宜有地区边界、路线差异、解锁次序、期限和清理机制。系统提供目标和理由，但战争成本、外交反应与军事结果仍由游戏承担。取得领土后再进入建设与治理，不把宣称、占领和整合压缩成一个奖励按钮。

### 6.6 地区成果属于实际参与地区

物理工程、行政标准和产业网络优先形成州级遗产，只作用于真正满足条件的州。全国奖励只在工程确实建立了全国性机关或制度时使用。

### 6.7 永久选择必须带来机会成本

永久制度可以强，但每个方向应放弃另一种能力、承担政治代价或改变地区与全国收益的分配。各选项应服务不同策略，不靠隐藏组合奖励逼迫玩家连续选择同一颜色。

### 6.8 长期治理循环保持国家特异性

常驻内容可以是双向平衡、可消耗储备、多支柱维护、单向结构压力，也可以是以后产生的新结构。只共享生命周期、安全和清理规则，不把所有国家塞进同一压力条模板。

### 6.9 失败留下后果，也保留继续游戏的空间

失败可以移除收益、留下衰减惩罚、保留已经完成的改革或要求经过冷却重建制度。除非内容本身就是不可逆历史结局，否则不要用一次失误永久锁死整条国家体验。

### 6.10 动态叙事始终准备降级文本

动态对象只承担脚本能证明的语义。对象消失、旧档缺少历史或作用域无法恢复时，应使用自然的无专名版本，而不是猜测前身、敌国或领土取得方式。

## 7. 叙事与本地化原则

### 7.1 让历史通过媒介进入当代

当代角色接触旧世界材料的媒介应当可理解，例如幸存档案、复制件、学校与宗教记忆、法典片段、礼仪、地名和政治宣传。国家可以选择性继承、重造传统或争夺解释权。

### 7.2 给政治主体明确位置

说明是谁在发言、谁承担成本、谁从制度中获益。国家机关、地方社会、利益集团、前所有者和战争对象不能因为一句宏大叙事而混为一谈。

### 7.3 文学性不能覆盖规则

事件正文可以营造气氛，JE reason、按钮和 tooltip 必须准确说明玩家需要知道的条件、期限、成本和后果。不要承诺脚本没有实现的法律、领土、人口或数值效果。

### 7.4 双语保持事实一致、表达自然

英文与简中应表达相同事实、因果和态度，但允许各自使用自然句式。专名和核心概念在模块内保持稳定；不要以逐词互译制造生硬的“历史感”。

## 8. 奖励、代价与节奏

- 奖励应体现玩家做成了什么：建成网络、稳定制度、达成妥协或长期维护国家能力。
- 永久全国增益保持克制；优先使用局部结果、原生政治反馈、内容解锁和相互排斥的制度收益。
- 强力正面效果应伴随机会成本、利益集团反应、财政负担、地区限制或长期维护要求中的至少一种。
- 高压力状态不必全部是红色减益；真实的短期收益可以解释玩家为何会容忍危险结构。
- 失败和恢复应属于同一个循环。冷却、遗留后果与保留成果共同制造历史感，而不是简单重置。
- 不要求每条路线数值镜像，但应让不同选择都有可理解的使用场景，避免一个选项在所有局面中显然最优。

## 9. 应避免的反模式

- **历史换皮**：把原版事件改名，却保留与 Firefall 时间线冲突的主体和因果。
- **古代制度直通未来**：没有解释中间断裂，就把旧制度写成持续存在。
- **清单式完整**：为了与另一个国家对齐而机械补齐事件、日志、Trait 或地区工程。
- **同模换名**：每个国家都使用相同进度、相同按钮和相同失败结构。
- **事件堆量**：没有新决策或状态变化的弹窗只会稀释关键节点。
- **无条件增益包**：身份、成立和每个里程碑都继续叠加全国 buff。
- **免费历史版图**：一次性授予广域永久宣称、免费战争能力或自动完成地区整合。
- **永恒废墟**：几十年后的治理与建设仍只描述灰烬、抢救和幸存者营地。
- **文本超前于脚本**：叙述不存在的法律、胜利、主权、持续时间或奖励。
- **隐藏改写历史**：普通政体变化、月度刷新或迁移逻辑悄悄替换已选路线。
- **为未来预建框架**：尚无第二个真实使用者时就创建通用风味引擎、配置层或跨地区状态总线。

## 10. 工具箱的扩展规则

新的风味设计要素满足以下条件时，可以加入本文：

1. 已在一个实际国家或地区模块中解决了真实体验问题；
2. 能抽象为其他模块可理解的设计问题，而不依赖原案例的专名和技术 ID；
3. 与现有组件存在清楚差异，或者能明显改进其适用边界；
4. 不要求已有模块为了形式统一而补做内容。

收录时优先补充一项组件、模式或反模式，不为每次小变化新增章节。Git 历史承担变更记录，不在本文维护第二套日志。

## 12. 开发前复核问题

这些问题用于发现多余或失真的内容，不构成必须逐项打勾的验收表：

- 能否用一句话说清玩家幻想和核心矛盾？
- 选用的每个组件是否增加了新决策、必要解释或可见反馈？
- 删掉某项内容后，核心体验是否仍然完整？
- 历史材料是否经过 Firefall 世界中的当代主体重新解释？
- 玩法是否真正区别于现有国家，而不只是换名？
- 文本、触发条件和实际效果是否陈述同一事实？
- 强力结果是否来自行动，并带有边界或机会成本？
- 失败是否既有后果，又允许游戏继续发展？
- 动态世界变化或旧存档缺失信息时，文本能否安全降级？
- 是否已经达到最小完整体验，可以停止增加内容？
